🎓 なぜ Hike プログラミング言語が CS / システムプログラミング教材に最適なのか？

💡 開発コンセプト & 制作意図
「C言語や本格的なアセンブリに進む前の『最初のウォーミングアップ』として、ポインタやバイナリの感覚を掴むのに最高の教材を作りたい」—— そんな想いから Hike Web Studio は誕生しました。Segmentation Fault や複雑なレジスタ操作で挫折することなく、ブラウザ完結でメモリや文字コードが視覚的に色づく体験を通じて、低レイヤの基礎感覚を自然と体得できます。

Hike の文法スタイルは Go 言語に非常に似ており、シンプルで可読性が高い という特長を持っています。 しかし、一般的な高級言語や Go 言語と決定的に異なるのは、「Zero-GC (ガベージコレクションなし)」「WASM ネイティブコンパイル」「直接的なリニアメモリ視覚化」 を標準備えている点です。

プログラミング学習において「メモリ内でデータがどう配置されているか」「ポインタやアドレスとは何か」「アルゴリズムによってメモリがどう変化するか」を頭の中だけで理解するのは容易ではありません。 Hike Web Studio では、コードを実行・デバッグしながら AST、LLVM IR、WASM 命令、および 0x0000 〜 0x0040 のリアルタイムメモリセル を同時に目視できます。

1. Go譲りの洗練されたシンプルな文法

複雑なC++の構文糖衣に悩まされることなく、`package main`, `func`, `var`, `for` などの明確な文法で本質的なロジックに集中できます。

2. メモリと文字コードの「見える化」

文字列リテラルがメモリ上で ASCII/UTF-8 バイト列として並ぶ様子や、ポインタ経由でアドレスを参照する仕組みが数値と文字で即座に視覚化されます。

3. アルゴリズムの段階的ステップ追跡

バブルソートの要素スワップやユークリッドの互除法の剰余変化、再帰呼び出しのコールスタック挙動を F10 (コマ送り) で完璧に観察可能です。

4. アセンブリ / WASM 直結の低レイヤ理解

高レベルな Hike コードがどのように LLVM IR に展開され、WASM の Stack-Machine 命令に変換されるかを対比学習できます。

演習 1: 1〜N の総和計算 (ループと変数)

初級 (Level 1)
📝 サンプルソースコード (main.hike)
package main
import "fmt"

func main() int32 {
    fmt.Println("演習1: 1〜5 の総和計算を開始します")
    var total int32 = 0
    for i := 1; i <= 5; i++ {
        total = total + (i * 10)
    }
    fmt.Printf("最終計算結果: %d\n", total)
    return total
}
🎯 教材としての狙い & 学習ポイント

プログラムの最も基本的な要素である「変数への代入」「条件付きループ」「算術演算」を学びます。 ステップ実行（F10）を行うと、ループの回数に同期して変数 `i` (アドレス `0x0000`) と `total` (アドレス `0x0004`) がどのように書き換わるかをメモリセル上で直感的に確認できます。

💡 デバッグの観察ポイント: メモリパネルの 0x0000Cell（変数 i）が 1→2→3→4→5 と更新され、0x0004Cell（変数 total）が 10→30→60→100→150 と加算される過程を黄色ハイライトで追跡してください。

演習 2: 文字列リテラルとポインタ操作 (メモリ文字コード確認)

初中級 (Level 2)
📝 サンプルソースコード (main.hike)
package main
import "fmt"

func main() int32 {
    fmt.Println("演習2: メモリ上の文字列リテラル 'HIKE' とポインタ操作")
    // メモリ 0x0008〜0x000B に ASCII 文字コード ('H'=72, 'I'=73, 'K'=75, 'E'=69) が配置される
    var strPtr *byte = ptr("HIKE")
    var char0 byte = *strPtr
    var char1 byte = *(strPtr + 1)
    
    fmt.Printf("先頭文字: %c (ASCII: 0x%X)\n", char0, char0)
    fmt.Printf("2番目の文字: %c (ASCII: 0x%X)\n", char1, char1)
    return int32(char0)
}
🎯 教材としての狙い & 学習ポイント

文字列が「文字の集合」ではなく「メモリ上の特定の先頭アドレスから連続して配置された文字コード（バイト配列）」であることを学びます。 ポインタ `*byte` と間接参照 `*strPtr` やポインタ演算 `*(strPtr + 1)` を通じて、C/C++やアセンブリと同等の低レイヤメモリ操作を体験します。

💡 デバッグの観察ポイント: メモリ表示を「🔢 16進数 (HEX)」に切り替えると、アドレス `0x0008` 〜 `0x000B` に `48` (`'H'`), `49` (`'I'`), `4B` (`'K'`), `45` (`'E'`) の 16 進文字コードが物理配置されているのが視覚確認できます。

演習 3: 配列要素の最大値探索 (配列と分岐)

中級 (Level 3)
📝 サンプルソースコード (main.hike)
package main
import "fmt"

func main() int32 {
    fmt.Println("演習3: 配列の最大値探索")
    var arr [5]int32
    arr[0] = 12; arr[1] = 45; arr[2] = 89; arr[3] = 34; arr[4] = 67
    var maxVal int32 = arr[0]
    for i := 1; i < 5; i++ {
        if arr[i] > maxVal { maxVal = arr[i] }
    }
    fmt.Printf("配列中の最大値: %d\n", maxVal)
    return maxVal
}
🎯 教材としての狙い & 学習ポイント

固定長配列 `[5]int32` がメモリ上で 4 バイトごとの連続領域（`0x0010`, `0x0014`, `0x0018`, `0x001C`, `0x0020`）として確保されることを理解します。 `if arr[i] > maxVal` による比較分岐によって、現在の暫定最大値 `maxVal` が 89 に到達した時点で更新が止まるアルゴリズムの分岐ロジックを学びます。

💡 デバッグの観察ポイント: `0x0018`Cell (arr[2] = 89) に到達した瞬間に `maxVal` が 89 に書き換わり、それ以降の 34 や 67 では `if` の条件が偽となり書き換わらない様子をスコープ変数パネルで追跡できます。

演習 4: ユークリッドの互除法 (最大公約数・アルゴリズム追跡)

中級 (Level 4)
📝 サンプルソースコード (main.hike)
package main
import "fmt"

func gcd(a int32, b int32) int32 {
    for b != 0 {
        r := a % b
        a = b
        b = r
    }
    return a
}

func main() int32 {
    var num1 int32 = 54
    var num2 int32 = 24
    fmt.Printf("演習4: %d と %d の最大公約数を計算中...\n", num1, num2)
    ans := gcd(num1, num2)
    fmt.Printf("最大公約数 (GCD): %d\n", ans)
    return ans
}
🎯 教材としての狙い & 学習ポイント

古代ギリシャ時代から伝わる最古のアルゴリズムの一つ「ユークリッドの互除法」の動作メカニズムを学習します。 `a = b`, `b = r` という変数更新スワップと、剰余演算 `%` によって、問題のサイズが急激に小さくなって収束する美しいループ構造を可視化します。

💡 デバッグの観察ポイント: 54 と 24 の計算ステップにおいて： 1ステップ目: `54 % 24 = 6` → `a=24, b=6`
2ステップ目: `24 % 6 = 0` → `a=6, b=0`
`b == 0` となり瞬時にループを抜け、最大公約数 6 が導き出される変遷をメモリ上で目視できます。

演習 5: 簡易的なバブルソート (配列の要素スワップ)

中上級 (Level 5)
📝 サンプルソースコード (main.hike)
package main
import "fmt"

func main() int32 {
    fmt.Println("演習5: バブルソートによる配列の昇順整列")
    var arr [4]int32
    arr[0] = 64; arr[1] = 34; arr[2] = 25; arr[3] = 12

    for i := 0; i < 3; i++ {
        for j := 0; j < 3-i; j++ {
            if arr[j] > arr[j+1] {
                temp := arr[j]
                arr[j] = arr[j+1]
                arr[j+1] = temp
            }
        }
    }
    fmt.Printf("ソート完了: arr[0]=%d, arr[3]=%d\n", arr[0], arr[3])
    return arr[0]
}
🎯 教材としての狙い & 学習ポイント

データ構造とアルゴリズムの基礎である「ソートアルゴリズム」と「一時変数 `temp` を介した値の入れ替え (スワップ)」を学びます。 2重ループによって隣り合う要素 `arr[j]` と `arr[j+1]` を比較し、大きい値がまるで泡 (Bubble) のように配列の末尾へ押し上げられていく挙動を視覚化します。

💡 デバッグの観察ポイント: 初期状態 `[64, 34, 25, 12]` から、ステップ実行を進めるたびにメモリ上の `0x0010`〜`0x001C` の値がリアルタイムで入れ替わり、最終的に `[12, 25, 34, 64]` に美しく並び替わる様子を確認してください。

演習 6: XOR データ暗号化と復号 (ビット演算)

中上級 (Level 6)
📝 サンプルソースコード (main.hike)
package main
import "fmt"

func main() int32 {
    fmt.Println("演習6: XOR ビット暗号化と復号")
    var secretKey byte = 0xAA
    var originalData byte = 0x42
    var encrypted byte = originalData ^ secretKey
    var decrypted byte = encrypted ^ secretKey
    fmt.Printf("暗号化: 0x%X -> 復号: 0x%X\n", encrypted, decrypted)
    return int32(decrypted)
}
🎯 教材としての狙い & 学習ポイント

コンピューターの根幹である「ビット演算（排他的論理和 XOR `^`）」の性質を学びます。 同じ鍵 `secretKey` で 2 回 XOR 演算を行うと元のデータに戻る（`(A ^ K) ^ K = A`）という数学的性質を利用し、暗号通信の基礎概念を理解します。

💡 デバッグの観察ポイント: `originalData` (0x42: 01000010) に `secretKey` (0xAA: 10101010) を掛けると `encrypted` (0xE8: 11101000) に化け、再度 0xAA を描けると見事に 0x42 へ復号されるビット変化を監視できます。

演習 7: 再帰関数 (フィボナッチ数列・コールスタックの挙動)

上級 (Level 7)
📝 サンプルソースコード (main.hike)
package main
import "fmt"

func fib(n int32) int32 {
    if n <= 1 {
        return n
    }
    return fib(n-1) + fib(n-2)
}

func main() int32 {
    var n int32 = 6
    fmt.Printf("演習7: フィボナッチ数 fib(%d) を再帰計算中...\n", n)
    result := fib(n)
    fmt.Printf("計算結果 fib(%d) = %d\n", n, result)
    return result
}
🎯 教材としての狙い & 学習ポイント

関数が自分自身を呼び出す「再帰呼び出し (Recursion)」と、呼び出しごとに生成される「コールスタック (Call Stack)」の概念を理解します。 ベースケース `if n <= 1` が存在しないと無限ループ（スタックオーバーフロー）に陥ることや、深さ優先で木構造状に計算が分解されていく過程を学びます。

💡 デバッグの観察ポイント: ステップ実行中に WASM (WAT) パネルを参照すると、`call $fib` 命令によって引数がスタックに積まれ（Push）、`return` で戻り値が消費されるスタックマシンの挙動が手にとるように分かります。

演習 8: Web API HTTP レスポンスパース (構造体メモリ)

上級 (Level 8)
📝 サンプルソースコード (main.hike)
package main
import "fmt"

type ApiResponse struct {
    status int32
    size   int32
}

func main() int32 {
    fmt.Println("演習8: Web API レスポンス解析")
    var res ApiResponse
    res.status = 200; res.size = 2048
    if res.status == 200 {
        fmt.Printf("通信成功! 受信サイズ: %d バイト\n", res.size)
        return 0
    }
    return 1
}
🎯 教材としての狙い & 学習ポイント

複数のデータフィールドをまとめる「構造体 `struct`」のメモリパディングと割り当てを学びます。 さらに「仮想サーバー連携モード」に切り替えることで、WASM モジュール間でのネットワーク通信や HTTP パケット解析の擬似体験が可能です。

💡 デバッグの観察ポイント: `res.status` と `res.size` がメモリ上の隣接領域（`0x0030`, `0x0034`）に格納される構造体バッファ構造を直接確認できます。

🔥 演習 9: Hike Web Studio 自身のセルフコンパイル

最上級 (Level 9)
📝 サンプルソースコード (main.hike)
package main
import "fmt"

type StudioEngine struct {
    version     int32
    memoryPages int32
    isSelfHost  bool
}

func (s *StudioEngine) InitStudio() int32 {
    s.version = 100
    s.memoryPages = 256
    s.isSelfHost = true
    return s.version
}

func main() int32 {
    fmt.Println("=== Hike Web Studio Self-Host Compiler Core ===")
    var studio StudioEngine
    status := studio.InitStudio()
    fmt.Printf("Studio Version: %d, Wasm Memory Block: %d Pages (16MB)\n", status, studio.memoryPages)
    return status
}
🎯 教材としての狙い & 学習ポイント

本 Studio 自体が Hike 言語で記述され、ブラウザ内でセルフホスト動作している究極のシステム構造を体感します。 構造体レシーバーメソッド `func (s *StudioEngine) InitStudio()` や 256 Pages (16MB) の大容量 Wasm メモリ境界領域の確保を追跡します。

💡 デバッグの観察ポイント: 最高度なセルフコンパイルコードの AST / LLVM IR 生成と 16MB 境界の Wasm 実行を、ブラウザ完結でリアルタイムデバッグできます。

🏫 授業・プログラミング講習・独学でのおすすめ進め方

  1. ステップ 1 (演習 1〜3): まずは変数・ループ・配列を「1行ずつ実行 (F10)」し、右下のメモリ画面で数字が変化する感覚を身につける。
  2. ステップ 2 (演習 4〜5): ユークリッドの互除法やバブルソートで、アルゴリズムの進行に伴い配列や変数の値が入れ替わる動的なドラマを追跡する。
  3. ステップ 3 (演習 6〜7): ビット演算や再帰関数を通じて、コンピュータ内部のスタックマシン命令や 16進数/2進数のビット操作の仕組みを理解する。
  4. ステップ 4 (演習 8〜9): 構造体・ネットワーク通信・セルフホストコンパイラへとステップアップし、本格的なシステムプログラミングの世界へ到達する。
